For AI assistants

Any assistant that speaks the Model Context Protocol can apply for the pension and follow it up on a citizen's behalf, with the citizen's sign-in. Officers get a separate endpoint with their own tools. Both follow the same rules as the form on this site: the assistant cannot get anyone a pension the counter would not.

Citizen endpoint{{ citizen_url }}
Officer endpoint{{ officer_url }}
TransportMCP over streamable HTTP
Sign-inOAuth 2.1 with PKCE, issued by this portal ({{ issuer }}). Citizens sign in with mobile and OTP, officers with the departmental login. The assistant never sees the OTP or the password.

Connecting from Claude Code

claude mcp add --transport http sewasetu-citizen {{ citizen_url }}
claude mcp add --transport http sewasetu-officer {{ officer_url }}

Then run /mcp inside Claude Code and choose Authenticate; the sign-in page of this portal opens in the browser. A citizen's sign-in lasts two hours, an officer's one working day.

What the citizen assistant can do

  • Explain the scheme and check eligibility (60 or above, one live application per person).
  • Fill the application one question at a time, attach the age proof (by a one-time upload link opened on the phone), read everything back, and submit only after the declaration.
  • Explain the status in plain words: who decided, when, why; which bank account the money goes to; the month the pension runs from; the yearly life confirmation.
  • Withdraw a pending application; raise a complaint when the money has not come; confirm the applicant is alive for the yearly certificate.

What the officer assistant can do

  • See what is waiting, oldest first, with the days left before automatic approval.
  • Look at one case with its audit trail, the things worth a second look, and the document.
  • Approve, or reject with a reason, recorded in the officer's own name. Close complaints.

Applications made through an assistant show "via assistant" on the officer's pages and in the audit trail. See also the evaluation dashboard.
